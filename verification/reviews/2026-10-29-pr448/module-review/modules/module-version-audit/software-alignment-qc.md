## MACS3: fixes present upstream, but do not overstate default ATAC impact

- The 3.0.5 fixes for [gap-score attribution](https://github.com/macs3-project/MACS/issues/741), [right-edge candidate loss](https://github.com/macs3-project/MACS/issues/747), and [shape clipping](https://github.com/macs3-project/MACS/issues/748) require `call_summits=True` / `--call-summits`. The normal pipeline does not set that option. User overrides could enable it.
- The 3.1.0 [control-duplicate threshold fix](https://github.com/macs3-project/MACS/pull/753) explicitly leaves `--keep-dup all` unchanged. Both ATAC peak-calling configurations set that option.
- The 3.1.0 [large-lambda Poisson repair](https://github.com/macs3-project/MACS/pull/777) states that no current command reaches the affected function and no reported number changes today. It is not evidence that this pipeline's reported p-values change.
- `bdgdiff`, `hmmratac`, and FRAG-specific fixes in those releases are outside the module's normal `callpeak --format BAM/BAMPE` execution.

## preseq: development fixes do not automatically implicate the release

The selected post-tag commits repair [mapped-read checks](https://github.com/smithlabcode/preseq/commit/251d39f057bc0a03892a0f39d7f6d89aef91070a), [priority-queue direction](https://github.com/smithlabcode/preseq/commit/094584aef999a0d4cd538051e6fa7b31c9361f1e), [mate ordering](https://github.com/smithlabcode/preseq/commit/0f896afc755d2f955a9ab15898defd598041807f), and [subcommand argument dispatch](https://github.com/smithlabcode/preseq/commit/bf88983bd67ffa47df47d79609b52c1e6e47d064). The [3.2.0 reader](https://github.com/smithlabcode/preseq/blob/v3.2.0/src/load_data_for_complexity.cpp) uses `SAMReader_deprecated` and explicit primary/mapped tests; the inspected development fix changes the later `bamxx` reader. No reproducer established the tagged runtime shares that defect. Two commits titled “Fixing vulnerability” only change [documentation-build Jinja2 requirements](https://github.com/smithlabcode/preseq/commit/3a0d6ca18770cc9578b3c8baf43f971616c090fe).

## Pipeline wiring and limits

Relevance was checked against the code landed by #448: [tool configuration](https://github.com/nf-core/atacseq/blob/a51bee0178045b29cd9f034e58f4de6b80bc91db/conf/modules.config), [MACS3 wrapper](https://github.com/nf-core/atacseq/blob/a51bee0178045b29cd9f034e58f4de6b80bc91db/modules/nf-core/macs3/callpeak/main.nf), [genome preparation](https://github.com/nf-core/atacseq/blob/a51bee0178045b29cd9f034e58f4de6b80bc91db/subworkflows/local/prepare_genome.nf), and the source URLs listed per tool in [software-alignment-qc.json](software-alignment-qc.json).

The strongest **used-command candidates for a separate validation** are deepTools matrix boundary behavior, Picard large-flowcell optical coordinates, and gffread large-field parsing. Each requires an input/option trigger and reproduction before calling it a pipeline finding. This is a release/history scan, not an exhaustive issue audit, resolved container inventory, binary test or proof that any version is bug-free. Nothing here authorizes changing the frozen HIV comparison runs or updating their module versions mid-campaign.

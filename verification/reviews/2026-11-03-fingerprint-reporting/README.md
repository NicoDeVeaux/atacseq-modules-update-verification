# Reproducible fingerprint reporting proposal

[Proposal branch](https://github.com/NicoDeVeaux/atacseq-nfcore/tree/proposal/reproducible-fingerprint-reports) at commit `826e7e` is a separate fork-only experiment based on upstream dev, tracked from [PR #476](https://github.com/nf-core/atacseq/pull/476). It does not change either upstream repair PR.

The branch captures actual controls task commands, raw fingerprint matrices, selected MultiQC configuration/source, observed versions and the two report exports before CI cleanup. A SHA256 manifest distinguishes complete capture from the raw nf-test outcome, including failures in a nonblocking latest-version lane. Artifacts expire after seven days; capture does not waive a failed test.

Control labels use `control::<treatment>::<control>` and a stage suffix. Colons are excluded by the real samplesheet checker. The version-bound MultiQC 1.13 helper protects this generated control identity from generic filename trimming and repairs float-keyed numeric TSV serialization. Existing treatment cleanup and explicit filename naming, full names, replacements and directory prefixes remain supported. Separate blocking reporting checks run on Nextflow 25.10.4 and 26.10.5 and feed the existing final CI gate. Reproduction commands are [beside the automated tests](https://github.com/NicoDeVeaux/atacseq-nfcore/blob/proposal/reproducible-fingerprint-reports/tests/regressions/fingerprint_reports.md).

Validated locally:

- Both engines pass eleven negative controls, all four nominal curves/286 numeric cells, the two-curve/152-cell `CASE.mLb.clN` witness and the four-curve/286-cell `mLb_A`/`mLb_B` witness. Reversed inputs preserve exact tables and curves. Independent actual-library review passes eighteen naming/parser/configuration checks.
- Fourteen collector tests pass, including valid leading-underscore samples. An action-shell smoke retains nf-test exits 0 and 23. Actual full-controls capture verifies all 25 retained files and identifies the failed snapshot result separately from complete capture.
- The original-label-format candidate completed all 253 tasks under Linux Nextflow 25.10.4. A final-source bridge reran its four real fingerprint producers and MultiQC successfully, preserving all eight curves and 782 numeric values. Raw bin rows reorder between producer executions, but their complete row multisets and quality numeric fields agree.
- Pre-commit formatting, whitespace and Nextflow lint checks pass. Standalone lint reports zero errors and the three existing warnings.

The old hash discrepancy now has an exact counterfactual reproduction. Changing only genuine retained raw-matrix headers to the original application labels, then choosing which file supplies each shared control last, reproduces both observed counts/plot MD5 pairs. Both legacy counts tables have zero numeric cells; two comparison-specific control curves are discarded. This establishes a concrete mechanism for the hash flip, while the historical CI files and actual iteration order remain unavailable. The reproduction is calibrated against an unchanged genuine eight-series numeric plot export before suppressing graphics work. See the [reproduction](LEGACY-HASH-REPRODUCTION.md) and [exact hash/order receipt](LEGACY-HASH-REPRODUCTION.json).

Its actual eight series/782 values match the unmodified parser exactly. Qualification of the final filename-option guard uses a separately bound full-context forward/reverse report replay; it does not claim another literal full 26.10 workflow with that final helper. The same candidate is source-derived for skip-consensus. The [default audit](DEFAULT-REPLAY-AUDIT.json) and [final-helper compatibility proof](DEFAULT-FINAL-HELPER-COMPATIBILITY.json) record that narrower scope; it is not an independent skip-consensus execution. A different-source replay demonstrates why matching an empty-table hash alone is insufficient: three curves and 225 point pairs differ despite the same old blank-table hash. The proposal does not claim a green complete pipeline matrix or native CI run.
